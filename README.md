# 双世界 MMO

工作室：云锦繁星。

Unity 客户端加六个 .NET 进程的 2.5D 双世界 MMO。P0 原型已收口：五个职业各一组技能带蓝条，真机上能换职业、能走位施法，Boss 分两个阶段按血线切换并出手打人。P1 从账号起：口令换令牌，战斗长连接只从网关进、网关只认令牌，建角色与进本走网关到角色服的 gRPC，深渊按人数扣疲劳、一天到 6000 封顶，温泉只把疲劳加回 1500，巢穴一周 12 个单人份、怪物按进本人数缩放，等级经验走同一笔结算、两人同场多一截少量加成。P1-3 从表世界起：八块首发地表按方案正文编号，人能进入一条分线，对话只在配置里，地表资源进已有的同一组 Launch AB；同一分线里的人按 5–10Hz 看到彼此的坐标与朝向，周围的人按距离分完整、简模、只留名字三档，档位由世界服给；矿和药能采，产物交给角色服进背包、疲劳不变，灵石矿脉不许个人采。

## 当前做到哪

**P1-3b 完成**（v1.74，2026-11-10）：采矿和采药。笔记本连库连服 52 项、Mac 客户端 6 项全过；平板重新出包后真机 P0-3c 59 项全过。

- 方案 9.5 只写定「矿给矿石、药给药材、采集不扣疲劳、灵石矿脉不开放给玩家个人采集」，产量、刷新秒数、入哪一格都没写定：`config/gather.json` 是唯一数值正本，四个节点（两个矿、一个药、一个灵石矿脉）。缺字段、非法 kind、地点不存在、灵石矿脉被配上产物或删掉灵石矿脉，世界服起不来；改产量与刷新重启即生效，代码里没有第二套数字。
- `proto/mmo/world.proto` 加 `Gather` 一元 RPC，请求只有 `account / character_id / node_id`，产物、数量、格子、事务号带不进；网关 `/world/gather` 认令牌、复核角色归属，业务拒绝回 200 + `ok=false`。世界服按未知节点 → 灵石矿脉 → 未进线 → 地点不符 → 占用中 → 发奖的顺序判定，节点占用与刷新只在进程内存、不落库。
- 采集成功复用角色服 `ApplyGrant`（`gather:<Guid>` 事务号 + 一条 `ItemDelta`），世界服不连角色库、不自己写背包、不碰疲劳 / 经验 / 货币；`grant_txn` 主键挡重放，同号再提交回 `duplicate`、背包不变。客户端 `Assets/Net/WorldGather.cs` 是 `noEngineReferences` 的纯 .NET 拆装，不用 `JsonUtility`。
- 连服证据：先 4 人深渊把疲劳打到 6000，采矿得 `ore_iron×2`、采药得 `herb_ling×3`，疲劳全程 6000；灵石矿脉回 `spirit_stone_forbidden` 且 `stone_1` 仍 0；请求体塞伪造的产物 / 数量 / 格子 / 事务号 / 账号，仍按配置发 2 个矿石。
- 本行先把脚本统一归位：`tools/` 是仓库里所有脚本的唯一存放处，顶层只放 `check/`、`env/`、`gen/`、`probe/` 四类目录，`deploy/` 只剩 systemd 单元；全仓路径引用一次改齐，核对命令统一 `bash tools/check/check-<卡号>.sh`。借这次把笔记本 P1 十六张卡、Mac E/P0 与四个客户端段全量回归一遍，全过。
