# 长生隙

双世界 MMO。名字取《梦长生》的「长生」，与外环隙、裂隙实例的「隙」——表里两界之间那道缝。工作室：云锦繁星。上图就是应用图标，源文件在 `client/MMOGame/Assets/Art/Icon/app-icon.png`；Android adaptive 图标的背景用这张插画、前景是全透明的 `app-icon-foreground.png`，换图后跑一次 `Assets/Editor/ApplyAppIcon.cs` 就会把各档槽位重新写一遍。

Unity 客户端加六个 .NET 进程的 2.5D 双世界 MMO。P0 原型已收口：五个职业各一组技能带蓝条，真机上能换职业、能走位施法，Boss 分两个阶段按血线切换并出手打人。P1 从账号起：口令换令牌，战斗长连接只从网关进、网关只认令牌，建角色与进本走网关到角色服的 gRPC，深渊按人数扣疲劳、一天到 6000 封顶，温泉只把疲劳加回 1500，巢穴一周 12 个单人份、怪物按进本人数缩放，等级经验走同一笔结算、两人同场多一截少量加成。P1-3 从表世界起：八块首发地表按方案正文编号，人能进入一条分线，对话只在配置里，地表资源进已有的同一组 Launch AB；同一分线里的人按 5–10Hz 看到彼此的坐标与朝向，周围的人按距离分完整、简模、只留名字三档，档位由世界服给；矿和药能采，产物交给角色服进背包、疲劳不变，灵石矿脉不许个人采；飞行和跨区认境界，没权限的飞请求被拉回地面。P1-4 从强化起：+12 上限分三档材料，失败只掉 1 级、不碎也不清零，概率只在配置里；保护券只挡住那一次掉级，不提高成功率，到账即绑、不分来源。

## 当前做到哪

**P1-4b 完成**（v1.77，2026-11-11）：保护券只挡掉级，不提高成功率。笔记本连库连服 53 项、Mac 客户端 6 项全过；平板重新出包后真机 P0-3c 59 项全过。

- 方案 9.2 / 12.1 写定：只有一种保护券、到账即绑、不能上架，商城与通行证付费轨以后发的是同一种，用的时候不看来源；券只挡住掉级，不提高成功率。`config/items.json` 里已有的 `ticket_protect`（voucher / always）就是这一种，`config/enhance.json` 加 `protect_item_id` 指过去，`EnhanceTable` 加载时校验存在 / 是券 / 是绑定 / 不与三档石头重合；发货（P1-5c2 / P3-4a2）不在本卡。方案没写「成功那一手扣不扣券」，按「只挡住一次掉级」取最小作用：只在实际挡掉掉级时扣 1 张，成功不消耗，也没有失败累计必成。
- 角色服仍是唯一写入方：`EnhanceRequest` 只多一个 `use_coupon` 开关，券编号 / 数量 / 来源 / 概率 / 结果都带不进；网关仍认令牌 + 复核归属 + 生成事务号。`EnhanceRepository` 在一笔事务里锁装备 → 查档 → 锁一格券（先不扣）→ 扣石头与金币 → 同一行 `tier.SuccessRate` 掷点 → 失败且用券时等级不变并扣 1 张券 → 写等级 → 提交；券不足、钱不够、用错石头整笔回滚。回包新增的 `success_rate / protected_level / coupon_used / coupon_left` 只作展示，客户端 `Assets/Net/CharacterEnhance.cs` 仍是纯 .NET 拆装。
- 连服证据：概率改 0 后不带券 `+4 → +3`、券 2 张没动；带券两次失败等级都停在 +3、券 2 → 1 → 0，第三次回 `coupon_insufficient` 且库里一格没动；带券与不带券回包的 `success_rate` 都是同一档的 0。改回 1 后带券成功 +1、券不消耗；再走发奖事务（商城 / 通行证发货路径）发同一种券，带券失败照样挡住掉级。券格 `can-trade` 回 `bound_item`。塞 `coupon_id / coupon_count / coupon_source / success_rate / protected_level / level / txn_id / account` 全无效，P1-4a 三档分界、+12 封顶、失败掉 1 级与幂等都不回退。
- 依赖闭包十张 P1 老卡、笔记本全量 22 张服务端卡、Mac 侧 E/P0 十张老卡全过；平板重新出包后真机 59 项全过，新包首次起来没被桌面抢前台。

**下一张**：P1-4c，强化转移——来源强化必须高于目标，成功后来源变为 +0。
