# 长生隙

双世界 MMO。名字取《梦长生》的「长生」，与外环隙、裂隙实例的「隙」——表里两界之间那道缝。工作室：云锦繁星。上图就是应用图标，源文件在 `client/MMOGame/Assets/Art/Icon/app-icon.png`；Android adaptive 图标的背景用这张插画、前景是全透明的 `app-icon-foreground.png`，换图后跑一次 `Assets/Editor/ApplyAppIcon.cs` 就会把各档槽位重新写一遍。

Unity 客户端加六个 .NET 进程的 2.5D 双世界 MMO。P0 原型已收口：五个职业各一组技能带蓝条，真机上能换职业、能走位施法，Boss 分两个阶段按血线切换并出手打人。P1 从账号起：口令换令牌，战斗长连接只从网关进、网关只认令牌，建角色与进本走网关到角色服的 gRPC，深渊按人数扣疲劳、一天到 6000 封顶，温泉只把疲劳加回 1500，巢穴一周 12 个单人份、怪物按进本人数缩放，等级经验走同一笔结算、两人同场多一截少量加成。P1-3 从表世界起：八块首发地表按方案正文编号，人能进入一条分线，对话只在配置里，地表资源进已有的同一组 Launch AB；同一分线里的人按 5–10Hz 看到彼此的坐标与朝向，周围的人按距离分完整、简模、只留名字三档，档位由世界服给；矿和药能采，产物交给角色服进背包、疲劳不变，灵石矿脉不许个人采；飞行和跨区认境界，没权限的飞请求被拉回地面。P1-4 从强化起：+12 上限分三档材料，失败只掉 1 级、不碎也不清零，概率只在配置里；保护券只挡住那一次掉级，不提高成功率，到账即绑、不分来源；强化转移要求来源高于目标、覆盖目标后来源归 +0，绑定规则跟着这笔事务走。

## 当前做到哪

**P1-4c 完成**（v1.78，2026-11-11）：强化转移，来源必须高于目标，成功后来源归 +0。笔记本连库连服 67 项、Mac 客户端 6 项全过；平板重新出包后真机 P0-3c 59 项全过。

- 方案 9.3 写定：来源强化必须高于目标，转移是覆盖不是相加，成功后来源变为 +0、目标变成来源原来的等级；不限部位；绑定装备的强化只能转给绑定装备，非绑转非绑目标仍可交易，来源绑定而目标未绑定时目标变为绑定（同一次事务里完成）；转移必定成功、不掷点，消耗金币和一枚转移石，费用随转出等级上升，转移石从巢穴来、商城不卖。
- `config/transfer.json` 是唯一数值正本（12 级递增费用、一枚转移石，数值待定），十一类坏配置都起不来，改费用重启生效；`config/items.json` 加转移石与一件可流通装备样本。`db/character/transfer.sql` 只加事务号防重放，强化等级和绑定仍存在原来的表里。角色服仍是唯一写入方：`TransferEnhanceRequest` 只有角色和两个格子，两格等级、绑定、材料、费用与结果都带不进；网关认令牌 + 复核归属 + 生成事务号，业务拒绝 200 + `ok=false`。`TransferRepository` 一笔事务里锁两行 → 校两格装备与来源高于目标 → 扣转移石与金币 → 必要时把目标绑定 → 来源写 0、目标写来源原等级 → 提交。客户端 `Assets/Net/CharacterTransfer.cs` 是纯 .NET 拆装。
- 连服证据：来源 +3 目标 +5 回 `source_not_higher` 且两格等级 / 绑定 / 金币 / 石头一格没动；相等、同一格、空格、不是装备同样被挡。来源 +5 目标 +3 成功后来源 +0、目标覆盖为 +5、扣 300 金币与 1 枚转移石，目标从非绑变为绑定；非绑 +6 转非绑 +2 目标仍可交易（费用 380 高于 +5 的 300）；非绑来源转已绑目标保持绑定。强化概率改成 0 重启后转移照样成功，费用从 120 改成 125 重启立刻生效；石头 / 金币不足整笔回滚（绑定也不生效）；伪造等级 / 绑定 / 金币 / 石头 / 事务号 / 账号全无效。P1-4a 三档分界、+12 封顶、P1-4b 保护券都不回退。
- 依赖闭包回归全过、Mac 侧 E/P0 老卡补跑全过；平板重新出包后真机 59 项全过，新包首次正常起来。
