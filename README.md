# 长生隙

双世界 MMO。名字取《梦长生》的「长生」，与外环隙、裂隙实例的「隙」——表里两界之间那道缝。工作室：云锦繁星。上图就是应用图标，源文件在 `client/MMOGame/Assets/Art/Icon/app-icon.png`；Android adaptive 图标的背景用这张插画、前景是全透明的 `app-icon-foreground.png`，换图后跑一次 `Assets/Editor/ApplyAppIcon.cs` 就会把各档槽位重新写一遍。

Unity 客户端加六个 .NET 进程的 2.5D 双世界 MMO。P0 原型已收口：五个职业各一组技能带蓝条，真机上能换职业、能走位施法，Boss 分两个阶段按血线切换并出手打人。P1 从账号起：口令换令牌，战斗长连接只从网关进、网关只认令牌，建角色与进本走网关到角色服的 gRPC，深渊按人数扣疲劳、一天到 6000 封顶，温泉只把疲劳加回 1500，巢穴一周 12 个单人份、怪物按进本人数缩放，等级经验走同一笔结算、两人同场多一截少量加成。P1-3 从表世界起：八块首发地表按方案正文编号，人能进入一条分线，对话只在配置里，地表资源进已有的同一组 Launch AB；同一分线里的人按 5–10Hz 看到彼此的坐标与朝向，周围的人按距离分完整、简模、只留名字三档，档位由世界服给；矿和药能采，产物交给角色服进背包、疲劳不变，灵石矿脉不许个人采；飞行和跨区认境界，没权限的飞请求被拉回地面。P1-4 从强化起：+12 上限分三档材料，失败只掉 1 级、不碎也不清零，概率只在配置里；保护券只挡住那一次掉级，不提高成功率，到账即绑、不分来源；强化转移要求来源高于目标、覆盖目标后来源归 +0，绑定规则跟着这笔事务走；能量结晶分攻击、防御、功能三类按部位限定，装上后可拆下带走复用，装上与拆下都不动强化、绑定和金币。

## 当前做到哪

**P1-4d 完成**（v1.79，2026-11-11）：能量结晶，装上后可拆下，部位不对的结晶被拒绝。笔记本连库连服 77 项、Mac 客户端 6 项全过；平板重新出包后真机 P0-3c 59 项全过。

- 方案第 9 章第 3 层写定：攻击 / 防御 / 功能三类、部位限定、可拆卸复用，换装时拆卸带走；9.1 写定结晶不改制作时掷定的基础属性；7.2 伤害公式里结晶是固定值而不是百分比（本卡不做伤害结算）；10 章写定结晶从副本掉落，商城与宗门 NPC 不卖。掉落发货、结晶合成升级、战斗服数值接入都在后面的卡。
- `config/crystal.json` 是唯一正本：三类写定，部位映射、每件装备的镶嵌位数与结晶固定值都从表里读并注明待定；`CrystalTable.Load` 校验类别不能被改名或增减、装备部位不能漏配、结晶必须是 `kind=crystal`、三类各至少一颗，二十类坏配置都起不来，改部位映射重启生效。`config/items.json` 加三种结晶与护甲、饰品两件装备样本。`db/character/crystal.sql` 只加 `crystal_socket`（镶嵌状态，含装上时的绑定状态）与 `crystal_txn` 防重放，强化等级仍在 `enhance`、绑定仍在 `inventory`。
- 角色服仍是唯一写入方：`InstallCrystalRequest` 只有角色、装备格、结晶背包格与镶嵌位号，`RemoveCrystalRequest` 只有角色、装备格与位号；类别、部位、能不能装、固定值、结果与事务号都带不进。网关认令牌 + 复核归属 + 生成事务号，业务拒绝 200 + `ok=false`。`CrystalRepository` 装上是同一笔事务：抢号 → 按格位升序锁两行 → 校装备与结晶 → 按类别查允许部位（不对回 `wrong_part`）→ 校验位号与空位 → 扣一颗结晶 → 写镶嵌行；拆下删镶嵌行并把结晶放回背包（优先叠回原堆叠格），绑定状态原样还回去。没有掷点，装上拆下都不扣金币、不改强化等级与绑定。客户端 `Assets/Net/CharacterCrystal.cs` 是纯 .NET 拆装。
- 连服证据：攻击结晶装到武器第 1 位成功后拆下，位子清空、背包结晶从 99 回到 100，还能再装到另一把武器；攻击结晶装到护甲回 `wrong_part`，装备与背包一格没动，防御 / 功能两类也各自按部位放行或拒绝。不是结晶、空格、位号越界、位已占用、拆空位都各自被挡。+7 非绑武器装上再拆下，强化等级、绑定、金币、结晶数量与 `can-trade` 全回到起点。把攻击类允许部位从 `weapon` 改成 `armor` 重启即生效，改回也生效；伪造类别 / 部位 / 结晶编号 / 位号数 / 结果 / 事务号 / 账号全无效，同一事务号在库里恰好一行。P1-4a / 4b / 4c 与 P1-1b3 / 1b5 / 2a / 2d 老规则不回退。
- 依赖闭包回归全过；平板重新出包后真机 59 项全过。
