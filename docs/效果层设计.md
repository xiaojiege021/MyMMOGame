# 效果层设计（Q1）

> 用途：把 Q1 定下来的效果表、交互规则、伤害四段与 PVE / PVP 边界写成一份可执行的契约。**Q1 只出设计与配置，不改代码**；Q2 才做 `StatusManager` + `DamagePipeline`，B10 才把强化 / 结晶接进副本伤害，B15 才铺具体技能与元素内容。
>
> 正本：`config/effects.json`（`effect-table/2`）。本页解释「为什么是这些键、这些键谁填」；字段级的校验规则另见[配置设计](配置设计.md) 第 13 节。

## 1. 一句话

效果层管两件事：**状态**（buff / debuff / 控制 / HoT / DoT / 护盾 / 净化）和**一次伤害怎么算**（方案 7.2 的四段乘区）。两件事都只在战斗服结算，客户端只显示回包事实。

## 2. 七类效果

| `kind` | 作用 | 必填键 | 样例 | Q2 运行时 |
| --- | --- | --- | --- | --- |
| `buff` | 正向属性修正 | `modifiers[]`（`stat` / `value`） | `buff_attack_up_1` 锐意（攻击 +10%，10 秒，3 层） | 进属性快照，按层数叠 |
| `debuff` | 负向属性修正 | `modifiers[]` | `debuff_defense_down_1` 破甲（防御 −15%，8 秒） | 同上，可被净化 |
| `control` | 控制：`root` / `slow` / `stun` / `silence` | `control` + `duration_ms`；`slow` 另要 `value_pct` | `cc_root_1` 定身、`cc_slow_1` 迟滞、`cc_stun_1` 眩晕 | 移动 / 施法限制；同类走 CC 递减 |
| `hot` | 按跳回血 | `duration_ms` / `tick_ms` / `amount_pct_max_hp` | `hot_regen_1` 回春（每 2 秒 5%，共 6 秒） | 服务端时钟驱动 |
| `dot` | 按跳掉血 | `duration_ms` / `tick_ms` / `modifiers[]` | `dot_poison_1` 蚀骨（每 2 秒 −3%，共 6 秒） | 服务端时钟驱动 |
| `shield` | 吸收伤害 | `duration_ms` / `amount_pct_max_hp` | `shield_1` 护盾（最大生命 20%，8 秒） | 先吃伤害，破盾即清 |
| `cleanse` | 按标签移除 debuff / control | `dispel_tags[]` | `cleanse_1` 净化（debuff + control） | 立即结算，不占持续槽 |

控制子类型：`root`（定身）、`slow`（减速）是方案写定的；`stun`（眩晕）、`silence`（沉默）先留键。**本轮只补 `cc_stun_1` 一条样例**，`silence` 仍只留键，等 B15 内容一起补，避免现在编技能。

## 3. 效果表字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 效果编号，全表唯一；技能 / 丹药 / 道具按它引用，不按名字 |
| `name` | 是 | 展示名；界面只显示这个 |
| `kind` | 是 | 七类之一，见上表 |
| `duration_ms` | 持续类必填 | `cleanse` 是瞬时效果，可以没有 |
| `tick_ms` | `hot` / `dot` 必填 | 必须整除 `duration_ms` 或明确最后一跳截断；Q2 按服务端时钟 |
| `max_stacks` | 否 | 默认 1；`stack_rule=stack` 时 > 1 |
| `stack_rule` | 否 | `refresh`（重置时长、层数不变）/ `stack`（加一层到上限）/ `independent`（各算各的时长，需实例号） |
| `modifiers[]` | `buff` / `debuff` / `dot` 必填 | `stat` + `value`；属性名只认 Q2 的固定集合，不在代码里写第二套 |
| `amount_pct_max_hp` | `hot` / `shield` 必填 | 按最大生命的百分比，整数 |
| `control` | `control` 必填 | `root` / `slow` / `stun` / `silence` |
| `value_pct` | `slow` 必填 | 移动速度修正，负数表示减速 |
| `diminishing` | `control` 建议 | 同类控制是否吃 CC 递减 |
| `dispel_tags[]` | 否 | 可被哪些标签的驱散 / 净化移除；按标签，不按来源编号 |
| `immunity_tags[]` | 否 | 命中这些标签的目标免疫本效果 |
| `pending` | 否 | 数值待定标记；Q1 的样例全部为 `true` |

**来源**不写在效果表里：同一个效果可以被多个技能、丹药、道具引用；谁施加、施加几层写在 `skills.json` / `items.json` 的 `effect` 块（B1 / B15 填），效果表只定义「是什么」。

## 4. 交互规则

| 规则 | 键 | 本轮口径 |
| --- | --- | --- |
| 打断 | `interaction.interrupt` | 只在**前摇**窗口内可打断；被打断时蓝耗按 100% 退回、技能进 1000ms 的「被打断」短冷却；数值待定，Q2 实现 |
| 硬直 | `interaction.hitstun` | 每个技能一条，来源是技能表 / 回包；默认 300ms，待定 |
| CC 递减 | `interaction.cc_diminishing` | 同一目标 15 秒窗口内，同类控制第 1 / 2 / 3 / 4 次时长按 100% / 60% / 30% / 0%（免疫）；曲线待定 |
| 叠层 | `interaction.stacking` | `refresh` / `stack` / `independent` 三选一，效果条目里写；叠加时是否刷新时长由 `refresh_on_stack` 定 |
| 驱散 | `interaction.dispel` | 按 `dispel_tags` 命中移除，不按技能编号写死 |
| 免疫 | `interaction.immunity` | 按 `immunity_tags` 判定，命中即整条效果不生效 |
| 净化 | `interaction.cleanse` | `cleanse` 类效果按标签移除 debuff / control；只移除、不返还已跳的 DoT / HoT |

## 5. 伤害四段（方案 7.2，逐字照抄）

```text
① 基础攻击 = (输出主属性 × 职业系数 + 装备固定攻击) × (1 + 境界加成)
② 强化后   = 基础攻击 × (1 + 强化系数 + 结晶固定值 / 基础攻击)
③ 技能伤害 = 强化后 × 技能倍率 × 克制系数
④ 最终伤害 = 技能伤害 × 防御减免 × (1 + 暴伤判定) × 随机浮动 0.95~1.05
```

| 段 | 输入从哪来 | 现在有没有 | 谁接 |
| --- | --- | --- | --- |
| ① 基础 | `classes.json` 的主属性、`attack_per_primary`、`equipment_attack`；境界加成来自战斗快照的 `passive_pct_bps` | 主属性 × 系数 + 装备固定已有；**境界加成没有进战斗快照** | Q2 补快照；境界 bps 已由 N10 算 |
| ② 强化 | 强化总级 / 强化系数、结晶固定攻击 | 只在战场 / 城战按「每级固定攻击」折算，副本伤害没接 | **B10** |
| ③ 技能 | `skills.json` 的 `damage_multiplier`、克制系数 | 倍率已有；克制没有表 | Q2 接倍率；克制等 B15 |
| ④ 最终 | 防御、暴击、随机、穿透、抗性 | 全没有 | Q2 + B10 |

**方案没写、Q1 补的口径**（全部标 `pending`）：

- **防御减免**：`1 - 有效防御 / (有效防御 + K)`，`K=100`、下限 10%；怪物防御现在是 8–40，K 与下限待数值卡确认。
- **强化段的除零**：`结晶固定值 / 基础攻击` 在 `基础攻击 <= 0` 时整项按 0 处理，不除零；Q2 落这条守卫。
- **暴击**：`(1 + 暴伤判定)` 展开成「暴击率 × 暴伤倍率」；默认暴击率 0%、暴伤 +50%，即默认不暴击，等 B2 / B10 给来源。
- **克制**：五行相克表还没有，默认所有系数 1.0；等 B15 内容定元素与表。
- **取整**：中间全程 `double`，**只在最终伤害四舍五入一次**；四段都是乘区，但先取整再乘会差出可见的数。
- **境界加成来源**：角色服把 N10 的 `passive_pct_bps` 放进战斗快照（`battle_profile.passive_pct_bps`），战斗服不另读一份境界表；这是第 4 类跨进程口径，Q2 落。

## 6. 穿透 / 抗性（已打开）

F3 的六个乘区里，穿透与抗性原先标「可选、默认关闭」；**Q1 按本轮决定改为打开**，但默认值是 0，所以不改变任何现有伤害：

```text
有效防御 = max(0, 防御 × (1 - 穿透% / 100))
防御减免 = clamp(1 - 有效防御 / (有效防御 + K), 下限 10%, 上限 100%)
最终伤害 = ... × 防御减免 × (1 - 抗性% / 100)
```

- **穿透**：`penetration.enabled=true`、`default_pct=0`、上限 100%；来源（装备 / 结晶 / 技能）等 B10 / B15，Q2 只把乘区接上。
- **抗性**：`resistance.enabled=true`、`default_pct=0`、上限 90%；按伤害类型取，类型先定 `physical` + 五行（`metal` / `wood` / `water` / `fire` / `earth`），当前所有技能按 `physical` 算，抗性 0。
- 默认值 0 时，第 4 段与方案 7.2 **逐字等价**；打开的是结构，不是数值。

## 7. PVE / PVP 边界

一句话：**效果与伤害管线只作用在战斗快照上；模板 / 1.3 / 科技在快照生成时已经生效，管线不许改模板属性。**

| 层 | 快照怎么来 | 管线在哪一步 | 不许做什么 |
| --- | --- | --- | --- |
| PVE | 角色职业 + 强化 / 结晶（B10 后） | 全额四段 | 不给副本单独加一层隐藏乘区 |
| 竞技场 | `config/arena_match.json` 的统一模板 | 模板属性进四段；模板没有防御时按 0 | 不许用真实装备属性覆盖模板 |
| 战场 | 装备全额先算战力，再按 `config/battlefield.json` 的同队系数压缩 | 压缩后的属性进四段；1.3 不是伤害乘区 | 不许把 1.3 再乘进最终伤害 |
| 城战 | 装备全额 + 宗门科技（`config/siege.json` / 科技表） | 科技乘在属性上，再进四段 | 不许另开一套城战伤害公式 |

数值仍只有一份：1.3 只在 `config/battlefield.json`，科技只在城战科技表，`effects.json` 只引用来源、不抄数字。

## 8. 状态的生命周期

- **服务端时钟**：DoT / HoT / 控制 / 护盾的剩余时间只由战斗服时钟算；客户端按回包的「剩余毫秒」倒计时，不本地推算。
- **死亡 / 结算 / 一场结束**：状态全部清空，护盾不跨场，DoT 不结算死亡后的跳。
- **掉线重连**：窗口内由 Q9 恢复剩余时长与层数；超出窗口按逃跑处理，状态不恢复。
- **客户端**：只画 buff 条与战斗日志（类型 / 剩余 / 层数 / 来源），不显示配置里没有的字段。

## 10. Q2 的落点（Q1 不做）

- `StatusManager`：每个战斗单位的 effect 实例（类型 / 剩余 / 层数 / 来源 / 下次跳）、死亡与结算清空。
- `DamagePipeline`：四段按本页第 5 节实现，读 `config/effects.json` 的 `damage` 段，不写第二套数字。
- proto 效果快照：类型 / 剩余毫秒 / 层数 / 来源（Q2 改 proto，按 D16 契约闸重出两端生成物）。
- 客户端 buff 条与战斗日志；只读回包。
- 强化 / 结晶的输入留给 B10，Q2 先把乘区接成恒等 1。

## 11. 不做

- 不改任何代码、proto、库表与配置现值（Q1 只写设计与配置）。
- 不铺具体技能、丹药、道具的效果引用（B1 / B15）。
- 不定五行相克表与元素技能（B15）。
- 不把穿透 / 抗性接成第二条公式；它们只是第 4 段的两个子因子，默认 0。
- 不做 PVP 专属伤害系数；模板 / 1.3 / 科技仍是各自那一层。
