# K2+Q13 卡片契约

> 风险标记 2/3（钱的写入口 + 协议拒绝码）。依据 [开发架构](../开发架构.md) 14.10 / 14.11 与 [不可逆点清单](../不可逆点清单.md)。
> 玩法正本：方案 `#s8`（城镇 / 宗门 NPC 卖什么、禁售清单）与 `#s11`（金币用途含修理）。

```text
卡号：K2+Q13
风险标记：2/3
本卡只做：
  - config/npc_shop.json 驱动城镇 / 宗门 NPC 的「买」：扣币 → 发货 → 记当日已卖 / 每人限购，同一事务；
  - 同一面板的「卖」（登记在册的可回收物品换金币）、「回购」（最近 5 笔，按配置倍率）、
    「修理」（按缺失耐久扣金币补满，单价与上限全在配置）；
  - 角色服是唯一写入方；网关加路由；客户端 UiShopScreen 加 npc 三段（买 / 卖 / 修）。
不做：
  - 不加货币、不动元宝与灵石口径；不做耐久消耗（战斗 / 死亡掉耐久归战斗结算卡）；
  - 不让装备、胚子、矿、药、灵石、境界丹、回春丹、气血丹、凝神丹、回灵丹、强化石、
    转移石、能量结晶进 NPC 货架（方案 #s8 禁售清单）；
  - 不动 shop.json（元宝商城）/ home_coin_shop.json / 拍卖 / 寄售 / 宗门专属商店的税分成；
  - 不做客户端本地算价、不做客户端改背包。
允许改：
  - config/npc_shop.json（v1 → v2：shops / sell / buyback / repair 四段，pending=false）
  - config/items.json 只允许「新增基础红药 / 基础蓝药两条」（schema 不升版）
  - src/Character/NpcShopTable.cs（新）、NpcShopRepository.cs（新）
  - src/Character/CharacterGrpcService.cs、CharacterProcess.cs（只加方法 / 注册）
  - proto/mmo/character.proto（只追加 message 与 rpc）+ 重出生成物
  - src/Gateway/ShopApi.cs（只加路由）
  - client/MMOGame/Assets/HotUpdate/Ui/UiShopScreen.cs、UiCommerceFlow.cs、UiCommerceCodex.cs
  - db/character/npc_shop.sql（新，character 版本 31）+ 追加进 db/character/character.sql
  - tools/check/check-k1.sh 商店区块；tools/probe/CliProbe/（新增 npc-shop 只读 / 写口）
冻结（一项都不许动）：
  - proto：BuyShopItemRequest / BuyShopItemResponse 已有字段编号与类型；其余已有 message
  - RPC / 拒绝码：既有 reason（not_in_list / not_on_sale / delivery_pending / goods_missing /
    bag_full / not_enough_yuanbao）语义不变；业务拒绝 = HTTP 200 + ok=false
  - DB 列 / 约束 / 迁移版本：inventory、character_equip、grant_txn、currency 已有列与约束；
    inventory.count CHECK(count>0)；迁移版本 1–30 只追加，不插号、不改旧文件
  - config 键 / schema：shop.json（shop-table/1）、items.json（item-table/4）、home_coin_shop.json；
    npc_shop.json 已有键名（id / npc_id / currency / refresh / items[].item_id / price /
    stock_per_day / limit_per_character）不改，只加段
  - 网关路径：/shop/buy 的路径与回包字段
状态与拒绝码：
  - 买：txn 带前缀 npc_shop_buy: → 抢 grant_txn → 条件扣金币 → 落包 → sold_today +1 /
    bought_today +1 → 提交；同一 txn 第二次只回 duplicate，不再扣发。
  - 卖：inventory 行删除与金币增加同一事务；卖出不留强化 / 结晶 / 穿戴记录。
  - 拒绝码：shop_unknown / npc_unknown / item_not_in_shop / stock_out / limit_reached /
    not_enough_gold / bag_full / not_sellable / buyback_empty / not_equipment /
    durability_full / txn_missing / duplicate。
  - 每个拒绝码旁边：金币变动 0、背包行数不变、库存与限购计数不变、耐久不变、
    不产生 grant_txn 行（duplicate 除外：只有原来那一行）。
不变量：
  - 金币守恒：买扣多少减多少、卖加多少增多少，没有第三方收款方；
  - 同一 txn 不双扣不双发（grant_txn 主键挡）；
  - 限购 / 日库存的上限由库里计数判定，配置只给上限；
  - 卖出的背包行删除后，character_equip / enhance / crystal 不悬挂（CASCADE 已验证）。
证据：
  - 静态：bash tools/check/check-k1.sh（商店区块新增项，不新建 check-k2.sh）
  - 真库：ubu 上 --npc-shop-buy / --npc-shop-sell / --npc-shop-buyback / --npc-shop-repair
    四个口各跑一次，读回金币、背包行、耐久、sold_today / bought_today；拒绝路径各跑一遍看余额不变
  - 变异：把「不扣币就发货」与「同一 txn 再发一次」改进去，期望 check-k1 红
回滚点：npc_shop.json 置 pending=true 即停用全部 NPC 商店入口（网关与客户端同时拒）；
        迁移 31 只加表 / 加列，回滚不删数据；配置改动重启生效。
```
