# B7+B8 卡片契约

> 风险标记 1/2（schema 与迁移顺序 + 钱的写入口）。依据 [开发架构](../开发架构.md) 14.10 / 14.11 与 [不可逆点清单](../不可逆点清单.md)。
> 玩法正本：方案 `#s12` 商城十二类里的「服饰 / 武器幻形 / 境界外观 / 飞行拖尾 / 坐骑外观 / 洞府与家园 / 宗门展示 / 背包与仓库」八行，以及「到达金仙才能买金仙外观」那条购买门槛。
> 开卡默认（用户 2026-11-22 回「继续」确认）：**7 类真发货 + 宗门展示暂缓**（宗门展示位在社交服没有落点，另卡）。

```text
卡号：B7+B8
风险标记：1/2
本卡只做：
  - 商城 8 类里 7 类接上发货：5 类外观（outfit / weapon_skin / realm_skin /
    flight_trail / mount_skin）、洞府与家园（home_decor）、背包与仓库（bag_expand）；
  - 5 类外观与洞府走「发一件对应种类的物品进背包」：外观收藏本来就是背包里
    外观类物品的账号级并集只读视图（WardrobeRepository），进包即进收藏，不新建收藏表；
  - 背包扩容走新的 `bag_expand` 发货方式：每买一次给这个角色 +step 格、到 max_slots 封顶，
    不往背包放东西；城镇 NPC 卖的「粗布背包」（kind=bag）同样按扩容处理，不留死物品；
  - 方案 12.1 的购买门槛：商品可选 `require_realm.enum_index_min`，境界不到回
    `realm_required` 且一分不扣（境界外观配成金仙段）。
不做：
  - 不做宗门展示（8 类里的第 8 类）——保持 delivery.mode=none，配置 note 写明暂缓；
  - 不做仓库扩容（方案同一行里的「仓库扩容」没有落点，背包只有一套格数）；
  - 不做「外观永久解锁表」：收藏仍按「现在持有」算，不记解锁历史；
  - 不做外观的穿戴 / 幻形切换界面（那是 U 系列与 B2 之后的事），只做「买得到、进得了收藏」；
  - 不动拍卖 / 寄售 / NPC 商店的价与税；不动月叠、通行证、第二角色栏三条已有发货分支。
允许改：
  - config/character.json（加 bag_expand_step / bag_slots_max 两键，bag_slots 仍是基础格）
  - config/shop.json（8 条商品的 delivery 段；新增可选 require_realm 段；note 里的暂缓说明）
  - config/items.json（新增 4 件外观占位物品；schema 不升版）
  - src/Character/ShopTable.cs（DeliveryMode 加 BagExpand；require_realm 校验）
  - src/Character/BagExpandRepository.cs（新）
  - src/Character/CharacterGrpcService.cs（分发加一路；各写入口的格数上界改成按角色现取）
  - src/Character/CharacterConfig.cs、CharacterProcess.cs（两键校验 / 只读入口 / 启动打点）
  - src/Character/BagRepository.cs 及 9 处读 `config.BagSlots` 的仓储（只换格数来源）
  - proto/mmo/character.proto（只追加 BuyShopItemResponse 的一个字段）+ 重出生成物
  - db/character/bag_expand.sql（新，character 版本 32）+ 追加进 db/character/character.sql
  - db/migrations.json（追加一条）
  - tools/probe/CliProbe/ShopCli.cs（只读与写口各一个 flag）
  - tools/check/check-k1.sh 商店区块
  - 客户端 UiShopScreen / UiCommerceFlow / CharacterShop 拆装件（只改回包读法）
冻结（一项都不许动）：
  - proto：BuyShopItemRequest 与 BuyShopItemResponse 已有字段 1–19 的编号与类型；
    其余已有 message 一个字不动
  - RPC / 拒绝码：既有 reason（not_in_list / not_on_sale / delivery_pending / goods_missing /
    bag_full / not_enough_yuanbao / duplicate / txn_missing / season_unavailable）语义不变；
    业务拒绝 = HTTP 200 + ok=false
  - DB 列 / 约束 / 迁移版本：inventory 的 slot CHECK(1..200) 与 count CHECK(>0)、
    grant_txn 主键、currency 的 (character_id, kind) 主键；迁移 1–31 只追加，不插号、不改旧文件
  - config 键 / schema：items.json 的 item-table/4、shop.json 的 shop-table/1、
    character.json 的 character-config/1；已有键名（bag_slots / delivery.mode / limit / stock）不改
  - 网关路径：/shop/buy 的路径与回包字段名
状态与拒绝码：
  - 外观 / 洞府：item 发货，state=delivered，delivered=true，bag_slot 给真落点；
    同一 txn 第二次只回 duplicate，元宝、背包、收藏都不动。
  - 背包扩容：state=bag_expanded，delivered=false，bag_slots 带回扩容后的格数；
    到达 max_slots 回 bag_slots_max（不扣元宝、格数不变）；重复买同一 txn 回 duplicate。
  - 境界门槛：realm_required（元宝 0、格数 0、背包不变）。
  - 每个拒绝码：charged_yuanbao=0、delivered=false、bag_slot=0、bag_slots=0（已生效的格数除外）。
不变量：
  - 元宝守恒：扣多少减多少，没有第三方收款方；同一 txn 不双扣不双发（grant_txn 主键挡）；
  - 背包容量 = min(base + count × step, max_slots)，`character.bag_expand_count` 只由扩容那一笔写；
  - 外观收藏 = 账号下所有角色背包里的外观类物品并集（不新增解锁表，不清洗历史）；
  - 买到的外观物品一律 bind=always，上不了拍卖（沿用 M 系列绑定口径）。
证据：
  - 静态：bash tools/check/check-k1.sh（商店区块新增项，不新建 check 脚本）
  - 真库：ubu 上 --shop-buy 七类各一次，读回元宝、背包行、bag_slots、--wardrobe；
    拒绝路径（已满 / 境界不够 / 同一 txn 重放 / 清单外）各一次，看余额与格数不变
  - 变异：把「先加格后扣钱」与「refund 后仍加格」改进去，期望 check-k1 红
回滚点：
  - shop.json 八条商品的 delivery.mode 改回 none 即停用全部新发货入口（网关与客户端同时回
    delivery_pending，一分不扣）；character.json 的两键只影响扩容上限；
  - 迁移 32 只加一列（默认 0），老角色容量不变；配置改动重启生效。
```
