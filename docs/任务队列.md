## Agent 取卡规则

1. 读本文件顶部的 `CURRENT` / `NEXT` / `STAGE` / `PLAN_GATE`。
2. 如果 `CURRENT` 不是 `—`，说明还有卡没收口：先确认那张卡是否已完成；未完成就不要开新卡，只报告「当前 X 还在进行中，下一张是 Y」。
3. 当前卡收口后：状态改 `完成`，`CURRENT` 置 `—`，再取 `NEXT`。
4. 取普通卡：状态改 `进行中`，`CURRENT` 改成该卡号，`NEXT` 改成队列里下一张「依赖全部完成」的 `待开始` 卡。
5. 按该行「详情」指向的章节读完成标准；只做那张卡，不提前做后面的卡，不改方案里已经写定的玩法。
6. 收口后：状态改 `完成`，`CURRENT` 置 `—`，重算 `NEXT`，在《开发日志》最上面写交付摘要——**这是唯一写进度的地方**，不回写 README / 开发架构 / 本文件的「当前」段。
7. 被依赖或外部环境挡住：状态改 `阻塞`，在回复里说明缺什么；**不要跳过**去取后面的卡。
8. 同一时间只允许一张 `进行中`；不并行、不合并两张卡。
9. **完成一个阶段的最后一张卡后**：不要直接开下一张；把 `PLAN_GATE` 改成 `yes`，`NEXT` 改成对应闸门号（`G1`–`G6`），先发阶段规划提醒。
10. 看到 `PLAN_GATE=yes` 或 `NEXT` 是 `G1`–`G6`：只发提醒，等用户回「继续」或给决策；**不要自动跨阶段**。
11. 看到卡号带 `★`：开卡前发一次「开卡前规划提醒」，列出这张卡要定的项与默认值；用户回「按默认」或给出决定后才开。
12. 用户回「继续」：`PLAN_GATE=no`，`NEXT` 改成闸门表里的「下一张」，`STAGE` 加 1，再按普通取卡。
13. 用户回「跳过规划」：记一次队列调整，`PLAN_GATE=no`，之后不再为这个阶段重复提醒。
14. 闸门提醒里必须写：刚完成的阶段、下一阶段、张数、第一张、要定的项、默认值。
15. 派卡前跑一次 `bash tools/check/check-structure-budget.sh`：红了先还结构债，不带着恶化往下派。
16. 到「结构转折点」那五处（见阶段闸门一节末表）必须停下来发重判提醒，判合并 / 拆分，不自动往下派。
17. 新卡的断言**默认并进同域已有 `check-*.sh` 的一个区块**，只有新域才准新建脚本；新建时 `scripts` 基线 +1 一起落账（开发架构 10.1）。
18. 进度只有一个写入点：**《开发日志》最上面一条**。README 讲项目是什么、开发架构讲规则与完成标准、本文件讲派工顺序，三处都不抄「vX 已收口」与通过项数；`bash tools/check/check-d7.sh` 守着这条（开发架构第 10 节「文档单一状态源」）。
