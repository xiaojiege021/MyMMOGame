## Agent 取卡规则

1. 读本文件顶部的 `CURRENT` / `NEXT` / `STAGE` / `PLAN_GATE`。
2. 如果 `CURRENT` 不是 `—`，说明还有卡没收口：先确认那张卡是否已完成；未完成就不要开新卡，只报告「当前 X 还在进行中，下一张是 Y」。
3. 当前卡收口后：状态改 `完成`，`CURRENT` 置 `—`，再取 `NEXT`。
4. 取普通卡：状态改 `进行中`，`CURRENT` 改成该卡号，`NEXT` 改成队列里下一张「依赖全部完成」的 `待开始` 卡。
5. 按该行「详情」指向的章节读完成标准；只做那张卡，不提前做后面的卡，不改方案里已经写定的玩法。
6. 收口后：状态改 `完成`，`CURRENT` 置 `—`，重算 `NEXT`，在《开发日志》最上面写交付摘要。
7. 被依赖或外部环境挡住：状态改 `阻塞`，在回复里说明缺什么；**不要跳过**去取后面的卡。
8. 同一时间只允许一张 `进行中`；不并行、不合并两张卡。
9. **完成一个阶段的最后一张卡后**：不要直接开下一张；把 `PLAN_GATE` 改成 `yes`，`NEXT` 改成对应闸门号（`G1`–`G4`），先发阶段规划提醒。
10. 看到 `PLAN_GATE=yes` 或 `NEXT` 是 `G1`–`G4`：只发提醒，等用户回「继续」或给决策；**不要自动跨阶段**。
11. 看到卡号带 `★`：开卡前发一次「开卡前规划提醒」，列出这张卡要定的项与默认值；用户回「按默认」或给出决定后才开。
12. 用户回「继续」：`PLAN_GATE=no`，`NEXT` 改成闸门表里的「下一张」，`STAGE` 加 1，再按普通取卡。
13. 用户回「跳过规划」：记一次队列调整，`PLAN_GATE=no`，之后不再为这个阶段重复提醒。
14. 闸门提醒里必须写：刚完成的阶段、下一阶段、张数、第一张、要定的项、默认值。

## 阶段规划提醒模板

```text
【阶段规划提醒】
阶段 {N}（{name}）已完成：{一句话总结}。
下一阶段：{name}，共 {n} 张，第一张 {card}。
开卡前需要你定的：{list}。
要现在做下一阶段规划吗？回「继续」按默认走，或先定这几项。
```

到 `★` 卡时按这个格式发：

```text
【开卡前规划提醒】
下一张 {card}（{title}）需要先定：{list}。
默认：{defaults}。
要现在定，还是按默认开卡？
```
