## E8 · 2026-11-07

一份 proto，两边生成同一份空消息。核对脚本 `tools/check-e8.sh`，7 项全过。

- proto 只有一份：`proto/mmo/common.proto`，包名 `mmo.common`，C# 命名空间 `Mmo.Proto.Common`，里面只有 `Empty`，没有玩法消息。
- protoc 不随仓库带。`tools/gen-proto.sh` 从 NuGet 取 `Grpc.Tools 2.85.0`（protoc 35.1），解到 `.tools/`，这个目录不进仓库。运行时 `Google.Protobuf 3.35.1`，和 protoc 35.1 同一条线。
- 生成物两处，内容逐字相同：`src/Shared/Generated/Common.cs`（服务端）、`client/MMOGame/Assets/Proto/Generated/Common.cs`（客户端，包在 `Mmo.Proto` 这个 asmdef 里）。
- 核对结果：两边都打印 `proto_type=Mmo.Proto.Common.Empty`、`proto_file=mmo/common.proto`、`proto_bytes=0`、`proto_roundtrip=ok`，客户端运行时版本 3.35.1.0。服务端跑 `tools/ProtoProbe`，客户端在 Unity 里跑 `Assets/Editor/E8Check.cs`。
- 踩到的坑：Google.Protobuf 3.35.1 的 netstandard2.0 包依赖 `System.Memory` 和 `System.Runtime.CompilerServices.Unsafe`。只放 `Google.Protobuf.dll` 时 Unity 报 `Unable to resolve reference 'System.Runtime.CompilerServices.Unsafe'`，整条 asmdef 都不加载。补上 `System.Memory`、`System.Buffers`、`System.Runtime.CompilerServices.Unsafe` 三个 dll 才通。这四个 dll 都在 `Assets/Plugins/Google.Protobuf`。
- 生成物里会有 Unity 生成的 `.meta`，比对时要排掉，脚本用 `diff -x "*.meta"`。

## E7 · 2026-11-07

HybridCLR 加载热更程序集，IL2CPP 补丁已装并能出包。核对脚本 `tools/check-e7.sh --build`，13 项全过。真机还没装。

- 包是嵌入式包：`client/MMOGame/Packages/com.code-philosophy.hybridclr`，版本 9.0.3，进仓库。**不能放 `client/packages/` 再用 `file:` 引**——安装器按 `Packages/com.code-philosophy.hybridclr` 这个固定路径找 `package.json` 和 `Data~/hybridclr_version.json`，放外面就读不到版本清单，`new InstallerController()` 直接抛异常。
- 热更程序集是 `Assets/HotUpdate`，asmdef 名 `HotUpdate`，`autoReferenced` 关掉，引用 `Mmo.Proto`。里面只有 `Entry`：`Version`、`Ping()`、`EmptyBytes()`。没有界面，没有伤害。
- 加载口在 `Assets/AOT/HotUpdateLoader.cs`：读 dll 字节，`Assembly.Load`，再反射拿 `HotUpdate.Entry`，全程不直接引用热更类型。
- **登记只能走一条通道**：`ProjectSettings/HybridCLRSettings.asset` 里 `hotUpdateAssemblyDefinitions` 登记 asmdef，`hotUpdateAssemblies` 必须为空。两条都登记，打包直接抛 `BuildFailedException: hot update assembly:HotUpdate is duplicated`。第一次打不出包就是这个原因。
- IL2CPP 补丁：官方安装按钮走 gitee 克隆，这台机器 `git-upload-pack` 被拒（`reject by [gitee]`）。改用 GitHub 镜像：`tools/fetch-il2cpp-patch.sh` 按包里的版本清单取 `hybridclr v9.0.1` + `il2cpp_plus v2022.3.x-9.0.1`，拼成 `libil2cpp` 目录放进 `.tools/il2cpp-patch`，再由 `Assets/Editor/E7Install.cs` 调 `InstallerController.InstallFromLocal` 装。装到 `Library/HybridCLR/LocalIl2CppData-OSXEditor/il2cpp`，106MB，版本文件写的是 `9.0.3`（包版本，不是 tag）。
- 打包时 `CheckSettings` 会把 `UNITY_IL2CPP_PATH` 指到上面那个补丁目录，并在没装或版本不一致时直接 `BuildFailedException`。所以「能打出包」本身就是补丁生效的证明。
- 实测出包：`build_result=Succeeded errors=0`，apk 21MB，里面 `lib/arm64-v8a/libil2cpp.so` 44875768 字节、`global-metadata.dat` 7103948 字节。`strings libil2cpp.so` 能看到 `HybridCLR.RuntimeApi::LoadMetadataForAOTAssembly`，路径也指到 `Library/HybridCLR/LocalIl2CppData-OSXEditor/il2cpp/libil2cpp`，说明用的确实是补丁过的源码，不是编辑器自带的。
- 打包输出路径踩坑：`BuildPipeline.BuildPlayer` 在这台机器上默认把结果导成 Gradle 工程（目录名就是 `MMOGame.apk`），要先 `EditorUserBuildSettings.exportAsGoogleAndroidProject = false`、`buildAppBundle = false` 才是 apk 文件。
- 核对输出：`hotupdate=ok asm=HotUpdate version=1 ping=hotupdate-ok empty_bytes=0 types=6 target=Android mode=current`。`empty_bytes=0` 说明热更程序集能用 proto 生成的类型。
- 生成物 `Assets/HybridCLR/Generate/{link.xml,AOTGenericReferences.cs}` 进仓库，改代码后 `GenerateAll` 会重写。
- 没做的：真机。这台机器没装 adb，也没有安卓设备，所以只到「apk 里有补丁过的 so」这一层，热更 dll 在手机上真跑起来还没验。E5 的真机安装同样挂着。

## E3 · 2026-11-07

systemd 拉起空进程，改代码走换进程。核对脚本 `deploy/check-e3.sh`，35 项全过。

- 单元是 `deploy/systemd/mmo@.service`，装到 `/etc/systemd/system/`，实例名用工程名（`mmo@Gateway`）。发布到 `/srv/mmo/app/<工程名>/<工程名>.dll`。
- 笔记本上另加了 drop-in `/etc/systemd/system/mmo@Gateway.service.d/user.conf`，把 `User` 和 `Group` 设成 `xiaojiege`。所以核对是在普通用户下跑的，不是 root。这个 drop-in 只在这台机器上，不进仓库。
- 环境：systemd 249（Ubuntu 22.04）、dotnet 10.0.403、`/srv/mmo/gamedb.env` 权限 600 在位。
- 启动：PID 3792950，`ready name=Gateway`，同名进程 1 个。
- 重启：3792950 → 3792983。旧 PID 已消失，日志里先有 `stopped`（SIGTERM 接住了），再有新进程的 `ready`。
- 换构建：程序集 sha256 从 `bc618ee5fa2b` 变成 `887ae905cd89`，新 PID 3793106，`/proc/<pid>/maps` 指向的是新 `Gateway.dll`，没有 `(deleted)`。
- 停止：`inactive`，`ExecMainStatus=0`，MainPID 归零，没有残留进程。
- 单元里没有 `ExecReload`，模板里也不写。改代码就是停旧进程、换文件、起新进程。
- 笔记：journald 异步落盘，进程刚起来那几百毫秒查不到 `ready`。脚本对日志断言做了 5 秒重试，第一次跑出 3 项假失败就是这个原因；另一处是模板注释里出现 `ExecReload` 字样被 grep 误判，已改成只匹配指令行。
- 这台笔记本上的仓库副本在 `~/MyMMOGame`，只有 `src/` 和 `deploy/`，是跑这张卡用的，不是正式检出。
