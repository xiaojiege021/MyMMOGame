# 多机同步

两台开发机加一台服务器：Mac 做客户端与文档，Windows 做客户端联调，Ubuntu 笔记本跑服务端和 `gamedb`。人从公司换到家，或者换另一台机器接着做，都按这一页。

## 一句话

代码走 Git，环境每台装一次，运行时只留一份在服务器上。

Git 只搬文件内容。它搬不动三样东西：Unity 与 IL2CPP 补丁这类二进制环境、`Library` 这类本机缓存、数据库和进程这类运行现场。所以别指望 `git clone` 之后就能直接打包，也别把 `Library` 塞进仓库。

## 三层

| 层 | 谁负责 | 具体是什么 |
| --- | --- | --- |
| 内容 | Git | `src/`、`proto/`、`client/MMOGame/Assets`、`Packages`、`ProjectSettings`、`config/`、`deploy/`、`tools/`、`docs/`、`.cursor/rules`。带 153 个 `.meta`，`.proto` 和生成物都在里面 |
| 环境 | 每台机装一次 | Unity `2022.3.62f3c1`、Android 构建模块与 SDK/NDK、IL2CPP 补丁（约 106MB）、`.tools/` 里的 protoc、本机 `~/.dotnet`（只有要在本机跑服务端或 E8 才需要） |
| 真源 | 只有 Ubuntu 笔记本 | `gamedb` 的数据、`/srv/mmo` 下的部署、systemd 单元、`/srv/mmo/gamedb.env` 里的口令。两台开发机连过去用，不复制回家 |

`.tools/`、`Library`、`Builds`、`Bundles`、`yoo`、`*.env` 都不进仓库，`.gitignore` 里写着。

## 换机器开工

```bash
cd MyMMOGame
git pull --rebase          # 先拉，别先改
tools/bootstrap.sh         # 体检 + 生成 proto + 跑 E8
```

`tools/bootstrap.sh` 会报这几件事：系统与架构、`git/curl/python3/dotnet` 在不在、工作区干不干净、落后远端几个提交、proto 生成物和仓库是否一致、E8 两端是否逐字相同、Unity 装在哪儿、IL2CPP 补丁有没有装。能自动做的它做掉，装不了的只报告不动手。加 `--quiet` 只体检不跑核对。

`.workbuddy/skills/` 也进仓库（`.gitignore` 里只放行这一层），派工用的 `dispatch-card` 技能随 `git pull` 一起过来。记忆文件 `.workbuddy/memory/` 不进仓库，它记的是本机的事。

**但文件过来不等于技能能用**，每台机要各做一次链接。WorkBuddy 扫描技能只看用户级目录 `~/.workbuddy/skills/`、内置技能和插件缓存，**不扫工作区下的 `.workbuddy/skills/`**——把技能放项目里，`Skill(dispatch-card)` 会报 `Can not find skill`，重开会话、重启都不管用。做法是让用户级目录指向仓库里那一份，别复制（复制会分叉）：

```bash
# macOS / Linux
ln -s "$PWD/.workbuddy/skills/dispatch-card" ~/.workbuddy/skills/dispatch-card
```

```powershell
# Windows（不需管理员）
New-Item -ItemType Junction -Path "$env:USERPROFILE\.workbuddy\skills\dispatch-card" `
  -Target "E:\unitywork\MyMMO\.workbuddy\skills\dispatch-card"
```

链接建完立刻生效，不用重启。判断有没有生效：`ls ~/.workbuddy/skills/dispatch-card/SKILL.md` 能读到，且 Agent 调一次 `dispatch-card` 能吐出「派工：卡片怎么发」就是好了。别拿 `~/.workbuddy/.skill-list-cache.json` 当依据，那是启动时的快照，新加的技能不会立刻写进去。

补丁没装时它会给步骤：`tools/fetch-il2cpp-patch.sh` 下载源码，再用 Unity 菜单里的安装项装进 `Library/HybridCLR`。这一步绕不过去，补丁按操作系统分开装，Mac 装的那份和 Windows 装的那份不能互拷。

## 四个真踩过的坑

**1. 两台同时改同一处会撞。** 现在改了立刻推，所以撞的概率不低。规则是先 `git pull --rebase` 再动手；万一两边改出同样的内容，rebase 会把本地那条当重复提交跳过，不留重复记录。真撞到冲突就以远端为底，只保留本机独有的改动。

**2. 换行符。** `.gitattributes` 已经固定：`.sh`、`.cs`、`.proto`、`.md`、Unity 的 `.unity/.prefab/.asset/.meta` 一律 LF，`.ps1/.bat` 用 CRLF，二进制文件标 `binary`。这样做是因为在 Windows 上编辑过的 `.sh` 会变 CRLF，拿到 Linux 上跑会以 `\r` 开头直接失败。

**3. macOS 的资源叉文件。** 从 Mac 往服务器或 U 盘拷文件会带 `._*`，进仓库会让 roslyn 报 `CS2015`。拷贝时用 `COPYFILE_DISABLE=1 tar`，或者拷完 `find . -name "._*" -delete`。仓库里现在一个都没有，保持这样。

**4. 权限位不跨平台。** 脚本里要造「不可写目录」时，`chmod 500` 在 NTFS 上根本不起作用——目录照样能写，核对会假失败，而且看起来像产品的错。`tools/check-p0-1b.sh` 第 11 段为此按平台分流：Windows 用 `icacls ... /deny "*S-1-1-0:(WD,AD)"`，只拒建文件和建子目录、**保留列目录**（连列目录一起拒的话，服务端启动时枚举结算目录会直接抛异常，根本走不到写那一步）；macOS 和 Linux 仍是 `chmod`。写这类脚本要记两点：Git Bash 里 `icacls` 的 `/deny` 会被 MSYS 当路径转换，得加 `MSYS_NO_PATHCONV=1`；账户名解析不稳，用 SID 才可靠。造不出场景时脚本打一行注意，不静默假通过。

## 各机的差异

| | Mac | Windows | Ubuntu 笔记本 |
| --- | --- | --- | --- |
| 主要干什么 | Unity 打包、核对脚本、文档 | 客户端联调 | 六个 .NET 进程、`gamedb` |
| IL2CPP 补丁 | `LocalIl2CppData-OSXEditor` | 装到自己的目录，别拷 Mac 的 | 不需要 |
| 核对脚本 | `check-e7.sh`、`check-e8.sh`、`check-p0-1a.sh`、`check-p0-1b.sh`、`check-p0-1c.sh`、`check-p0-1d.sh` 都能直接跑 | 能跑 `check-e8.sh`、`check-p0-1b.sh`（第 11 段走 ACL，见上面第 4 个坑）；`check-e7.sh`、`check-p0-1a.sh`、`check-p0-1c.sh` 要用 `UNITY=` 指到本机编辑器；`check-p0-1d.sh` 还没在 Windows 上跑过（它靠 `kill -9` 造崩溃现场） | `deploy/check-e3.sh` |
| dotnet | `~/.dotnet/dotnet`，不在 PATH 上，脚本自己找 | 装 10.0.403 | 10.0.403，系统里 |

Unity 版本必须逐字相同：`ProjectSettings/ProjectVersion.txt` 写的是 `2022.3.62f3c1`，Hub 目录名常写成 `2022.3.62f3`。差一个补丁号，打开工程会重转资源，打出来的 AB 也对不上。

## 口令和地址

口令不进仓库，也不写在这页。服务端要的口令在 Ubuntu 笔记本的 `/srv/mmo/gamedb.env`，从 Mac 连库时用局域网 `192.168.1.117:5432`，其他网络走 `YOUR_SERVER_IP:15432`。仓库地址是 `ssh://git@YOUR_SERVER_IP:2222/xiaojiege/MyMMOGame.git`。

U 盘不是同步手段，只当作一次性搬运。里面的东西用完就该删。
