# 换装挂点清单

这份清单是 `docs/开发架构.md` 第 17 节 17.2 第 2 条要求的那份**前置契约**：全职业共享一套骨骼，外观按「挂点 + 部件分类 + 染色参数」组合，不按成套模型整包替换。按第 17 节，「这份清单必须在 P1-5 这一批卡开工前定死」，本文件即定死的正本。

**只定接口，不定风格比例、画法和色板。** 不改前面任何章节的编号，不改第 14 节的行序，不新增任务卡，不占任何一行的完成标准，也不进 `config/`——`config/` 里仍然只有权威数值，没有美术字段。玩法以 `docs/MMO系统架构方案.html` 为准，进程边界以 `docs/技术架构.md` 为准。

## 1. 为什么必须先定

角色服的商城资产、背包里的幻形、通行证发的当季外观与洞府摆件，都会决定「一个外观在库里用什么标识」。若按现在的占位模型写成一个贴图 ID 或单串，等真模型要拆部件时，动的就是角色库 schema 和那笔发奖事务——那是全项目最不该回退的地基。所以先把挂点名、部件枚举和标识形状定死，再写发货。

## 2. 骨骼层级

- 全职业共用一套人形骨骼，标识 `rig_version`，从 1 起。骨骼改版时整批外观带版本号，旧版仍要能解析。
- 根节点始终是**逻辑节点**：独立的逻辑碰撞体和 `TargetEntity` 挂在父节点上，视觉模型挂子物体。第 17 节 17.2 第 1 条不变——模型可以换，碰撞体和锚点不能跟着换；`TargetPicker` 的 `Physics.Raycast` 和 `BattleScene` 的 `WorldToScreenPoint` 仍以现有占位实体为准。
- 挂点统一是骨骼下的空节点，名字即下表第一列，不随模型资源改。
- 动画只作表现（17.2 第 4 条）：`foreswing_ms` 是服务端权威数值，动画事件不触发命中、结算和冷却。

## 3. 挂点命名

命名规则：全小写加下划线，`socket_` 前缀；左右件用 `_l` / `_r` 后缀；**只追加、不改名**。改名等于同时改角色库里已发的外观和所有已出的 AB 地址。新增挂点必须先登记进这张表，再出资源。

| 挂点名 | 位置 | 承载什么 | 约定 |
| --- | --- | --- | --- |
| `socket_root` | 根节点 | 不挂视觉模型 | 逻辑碰撞体与 `TargetEntity` 所在层，锚点不随模型变 |
| `socket_body` | 躯干 | 衣服主体 | 视觉模型一律挂子物体 |
| `socket_head` | 头 | 头部服饰、头盔 | |
| `socket_hair` | 头顶 | 发饰 | |
| `socket_face` | 面部 | 面部部件 | 暂不启用，位置先留出来 |
| `socket_neck` | 颈肩 | 领口、披风扣 | |
| `socket_shoulder_l` / `socket_shoulder_r` | 左右肩 | 肩甲 | 左右按 `_l` / `_r`，不写 `left` / `right` |
| `socket_chest` | 胸 | 胸饰 | |
| `socket_back` | 背 | 披风、翅膀 | 飞行拖尾另用 `socket_trail` |
| `socket_waist` | 腰 | 腰带 | |
| `socket_hand_l` / `socket_hand_r` | 左右手 | 武器、武器幻形 | 主副手由职业与分支决定，挂点名不跟着职业走 |
| `socket_hip_l` / `socket_hip_r` | 左右腰侧 | 挂饰 | |
| `socket_leg_l` / `socket_leg_r` | 左右腿 | 护腿 | |
| `socket_foot_l` / `socket_foot_r` | 左右脚 | 鞋 | |
| `socket_trail` | 根 / 脚下 | 飞行拖尾 | 挂点不决定能不能飞，飞行仍由境界开放 |
| `socket_mount` | 坐骑锚点 | 坐骑外观 | 只换样子，不叠速度、不进战斗 |
| `socket_title` | 头顶 | 称号牌 | 称号不加属性 |
| `socket_aura` | 根 | 境界光效、入场动作特效 | 只作表现，不触发结算 |

洞府与家园、宗门展示（山门、旗帜、披风）不挂角色骨骼，属于场景锚点，按第 17 节 17.2 第 3 条「文件名即 AB 地址」单独归位，不进这张表。

## 4. 部件分类

`category` 是稳定枚举，只追加不改名。分类按方案 12.1 的上架种类映射，不另立一套商品名。`part` 是同一分类下的子件，也是稳定枚举。

| `category` | 对应的方案 12.1 种类 | 典型 `part` | 挂点 | 边界 |
| --- | --- | --- | --- | --- |
| `outfit` | 服饰外观（衣服） | `body` `head` `shoulder` `waist` `leg` `foot` `cape` | 第 3 节对应挂点 | 只改样子 |
| `dye` | 服饰外观（染色） | 按材质槽，不占挂点 | 无 | 染色只动服饰，不改种族 |
| `weapon_skin` | 武器幻形（十八般、弓、弩、法杖） | `main_hand` `off_hand` | `socket_hand_l` / `_r` | 按职业和分支出售，不改装备数值与分支技能 |
| `realm_outfit` | 境界外观（首发炼体、筑基、结丹） | 同 `outfit` | 同 `outfit` | 到达该境界后才能买，不卖境界、不卖加速 |
| `trail` | 飞行拖尾 | `trail` | `socket_trail` | 没飞行权限时拖尾不让人飞 |
| `mount_skin` | 坐骑外观 | `mount` | `socket_mount` | 纯外观，不叠加速度、不进战斗 |
| `title` | 称号 | `title` | `socket_title` | 不加属性，不代替身份 |
| `entrance` | 入场动作 | `entrance` | `socket_root` + 动画状态 | 只作表现，不触发结算 |
| `home_decor` | 洞府与家园 | `home` `furniture` | 场景锚点 | 只做展示和生活 |
| `sect_display` | 宗门展示 | `gate` `banner` `cloak` | 场景锚点 | 别人进驻地能看见，不卖宗门科技与领地加成 |

`part` 枚举初值：`body` `head` `shoulder` `waist` `leg` `foot` `cape` `main_hand` `off_hand` `mount` `trail` `title` `entrance` `home` `furniture` `gate` `banner` `cloak`。新增部件只往枚举里追加。

## 5. 染色参数

- `dye_params` 是「材质槽标识 → 染色参数」的键值集合，不写成单串、不写死颜色值。
- 染色只动服饰，不改种族；称号、拖尾、坐骑外观没有染色语义就留空集合，不用空串占位。
- 具体材质槽数量与参数取值域待定，等第一批标定资源进场时补，**不改本清单的结构**。

## 6. 外观在库里的标识

一个外观**资产**由这组字段共同标识，缺一项都不算完整：

```
asset_id       稳定编号，命名规则 <category>.<part>.<variant>
category       第 4 节的枚举
part           第 4 节的枚举
rig_version    第 2 节的骨骼版本
sockets[]      第 3 节的挂点名数组
dye_params     第 5 节的键值集合
prefab_address 资源文件名即 AB 地址（17.2 第 3 条）
```

角色持有外观时写 `character_id + asset_id + category + part + dye_params + acquired_at + bound`，不把整套外观压成一个贴图 ID 或单串。服务端只存标识、归属与绑定，不存模型本身；`prefab_address` 由客户端按 `AddressByFileName` 解析，不进 `config/`，也不进服务端判定。

发奖事务按 `asset_id + category + part` 一次写入。以后真模型要拆部件，扩的是 `part` 枚举和 `sockets[]`，不动角色库的主键形状，也不重写已发出的外观。三个 schema 的分工仍按技术架构第 6 节：角色数据写角色 schema，拍卖行写交易 schema，不因为外观多开一套库。

## 7. 演进与核对

- 挂点名、`category`、`part`、`asset_id` 命名规则都只追加不改名；新增资源先登记清单再进包，没登记的资源不进包。
- 换资源只换内容、不改文件名；`AddressByFileName` 下文件名就是 AB 地址。手写的 `.meta` GUID 必须正好 32 位十六进制。
- 整批替换按 17.4 灰度：先一个副本或一块地表 → 真机 P0-3c 的 59 项看点选与坐标 → 依赖闭包 `--card` → 铺开 → 里程碑 `--full`。逻辑碰撞体与锚点不动是这几步的底线。
- 服务端不读模型，配置不写美术字段，客户端不把外观标识当成伤害或交易的权威输入。

## 8. 与后面卡的关系

这份清单只定接口。P1-5c1 商城清单、后续外观发货、P3-4a2 通行证与 P3-4b 月叠按这份清单写「一个外观在库里用什么标识」；外观能否上架、能否绑定、绑定后能否解开，按方案 12.1 与 P1-5c8，本清单不写死。P1-5a 只做拍卖成交的销毁税，不读也不写外观字段。
